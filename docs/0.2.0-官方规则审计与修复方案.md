## 三、问题项与修复方案

### A（P1）字面颜色硬编码 → 暗色主题必坏

**规则**：practices.md——「样式只用 `cordis_inspect_query Theme` 列出的主题 token（`--dsw-alias-*`）；字面颜色仅限艺术作品（artwork）」。官方验证清单（SKILL.md 第 4 步）明确要求 "reads correctly in light and dark themes"。

**现状**：client.js 约 40 处硬编码 hex。重灾区：

| 位置 | 现值 | 暗色后果 |
|---|---|---|
| `.dcards-card` 背景与 `.dcards-pagebar select` | `#fff` | 暗底上刺眼白块 |
| `.dcards-name` / `ROW_STYLE.color` | `#1f2733` `#3a4150` | 暗底上文字几乎不可读 |
| `BTN_GHOST_STYLE` 边框/背景 | `#d4d9e0` / `#fff` | 同上 |
| `.dcards-skel` 渐变 | `#f2f4f8→#e9edf3` | 骨架屏变成白条 |
| CardsNodeView 文字 | `#8a8f99` | 浅色低对比 + 暗色不可读 |

**修复方案**：
1. 在本地源码 checkout 启动 0.2.0-rc.2，用 `cordis_inspect_query` `Theme`（或直接读 `packages/client` 的 token 定义文件）拿到 token 清单——**token 名不能凭空猜，写错即回退失效**。
2. 建立映射表（示例占位，实际以查得为准）：文字主色/次要色/边框/卡片背景/悬停/主按钮/骨架屏 → 各自 `var(--dsw-alias-*)`。
3. 分类徽章色板（CATEGORY_COLORS，9 色）与其它「艺术性」用色按规则可保留字面色，但建议给文字配 token 前景。
4. 回归：浅/深两主题各过一遍市场页 + 设置卡片 + 对话节点。

**工作量**：查 token 半天 + 替换与回归 1 天。**依赖**：本地 dsh 源码环境（D 盘已有 checkout）。

### B（P1）缺展示元数据 → 0.2.0 插件管理卡片回退默认

**规则**：host-plugin.md——Plugin Manager 卡片、bundle 详情、Settings 清单从 manifest 读 `meta.title/description`（`locale/en.json`，`locale/zh.json` 同字段）与顶层 `icon`（相对路径，SVG/PNG/JPEG/WebP ≤256KiB，禁绝对路径/URL/符号链接越界）；缺省回退 `name` + `description` + 默认图。配套要求 exports 声明 `./package.json` 与 `./locale/*.json`，`files` 包含 `locale/*.json` 与 `icon.svg`。

**现状**：package.json 无 `meta`、无 `icon`、无 `locale/`；`files` 只有 `lib` + `cordis.patch.yml`。0.2.0 恰好重点增强插件管理界面（rc.1/rc.2 changelog 两度提及）——现在不补，等于在官方新门面上挂着英文名 + 默认占位图。

**修复方案（可离线立即执行）**：
1. 新增 `locale/en.json`、`locale/zh.json`：`{ "title": "Plugin Cards（设置卡片+对话节点+插件市场）", "description": "…" }`（en/zh 各写各语言）。
2. 新增 `icon.svg`（自绘小鲸鱼/卡片图形，<10KB）。
3. package.json 增补：
   ```json
   "meta": { "title": "...", "description": "..." },
   "icon": "./icon.svg",
   "exports": { "./package.json": "./package.json", "./locale/*.json": "./locale/*.json" },
   "files": ["lib", "cordis.patch.yml", "locale/*.json", "icon.svg"]
   ```
4. 发布流水线无需改（files 之外不进包）。

### C（P1）UI 文本未走 locale 服务

**规则**：ui-plugin.md——「可见 UI 文本一律经 Client locale 服务」。

**现状**：硬编码中文约 30+ 处（`'社区插件'`、`'配置加载中…'`、`'启用插件'`、market 全部筛选标签/按钮/提示）。英文环境用户全程看中文。

**修复方案**：
1. 文案表双语化（en/zh），客户端启动时从 `ctx.locale`（注入清单加 locale 服务名，以 `cordis_inspect_query` 确认服务名后写定）读取当前语言。
2. 分批落地：第一批高可见面（settings.section label、config card 状态行、market 分页/按钮），第二批 market 筛选标签与分类名。
3. 与 A 项同一次发布（0.9.0）合入，避免两次全量回归。

### D（P2）缺 0.2.0-rc.2 实测验证记录

**规则**：verification.md——无浏览器控制时至少验证 JS 语法、manifest 校验、live Client slot；SKILL.md 要求确认 console 无 `slot entry crashed`、双主题正确。

**现状**：docs 截图验证止于本地构建 0.2.x 早期（verify-0.2.2 / verify-catalog-0.2.4）；0.2.0-rc.1/rc.2 发布后未跑回归。engine 保持 `>=0.1.7-rc.2` 是对的（0.2.0 无破坏变更，收窄会误伤老桌面端），但「已验证」声明需补。

**修复方案（需本地环境，非代码改动）**：
1. 源码 checkout 切 `dsh-v0.2.0-rc.2`，`pnpm dsh web --patch cordis.dev.patch.yml`。
2. 过清单：`--dump-config` 出现本包层 → 市场页/设置卡片/对话节点三面回归 → console 无 slot crash → 浅/深主题。
3. 结果记入 README 版本锚定行与本文档。

### E（P2）剪贴板兜底绕过组件写 DOM

**规则**：practices.md——「不要在组件外写 DOM、不要往 `document.body` 追加节点」。

**现状**：client.js L1889 复制兜底 `document.body.appendChild(ta)`（瞬时 textarea → select → copy）。

**修复方案**：优先 `navigator.clipboard.writeText`；失败兜底改为组件内渲染隐藏节点（随卸载清理）或保留现做法但加注释说明豁免理由（瞬时、同帧移除）。低风险小改，可与 B 一起发。

### F（P3）README 安装段过时

0.2.0-rc.2 起桌面端菜单栏内置 dsh 命令管理插件，**不再需要 Node/pnpm**。README「命令行备选」整段（pnpm v12 一致性、删 metadata 缓存）降级为「0.1.x 旧版用户备注」，主路径改为桌面端市场安装 + 设置内安装引导。
